# 走线路径约束与整理

`pcb_route_track` 和 `pcb_auto_route_nets` 使用 `src/routing-geometry.ts` 中同一套路径策略。手工给定路径和内置自动路径都要经过角度约束及障碍复查。

路径整理与端点绑定已完成本地构建、生成处理器测试和回归测试。焊盘端点修复还在真实 EDA 上完成了只读 dry-run 验证；没有在用户正在手工修正的 PCB 上做写入测试。

## 参数

坐标及距离单位均为 mil。普通焊盘中心不再通过网格取整；遇到歧义、超出端点移动范围、零长度收尾或修正后碰障碍，会拒绝写入并报告原因。

| 参数 | 默认值 | 行为 |
| --- | --- | --- |
| `angleMode` | `octilinear` | 允许水平、垂直和 45° 对角线。`orthogonal` 仅允许水平/垂直；`free` 显式允许任意角度。 |
| `cornerStyle` | octilinear 为 `chamfer`，其余为 `preserve` | 倒角模式用 45° 过渡整理直角；空间不允许且不是保护锚点时，预检报错。 |
| `chamferDistance` | 10 | 倒角沿相邻线段回退的目标距离，必要时缩小；不会吃掉相邻倒角。 |
| `minSegmentLength` | 1 | 整理后仍短于该值的线段单独提示，不为消除短线而移动连接端点。 |
| `maxDeviation` | 10 | 整理后的整段路径必须处于原始路径的该距离范围内。 |
| `angleToleranceDeg` | 0.01° | 读回角度检查容差；限制在 0–1°。生成路径以共轴/等量 XY 增量构造，不靠该容差放行斜线。 |
| `endpointMode` | `auto` | 只识别端点接触的同网同层铜：普通焊盘/过孔接中心，导线接中心线。`preserve` 保留未显式绑定的首尾坐标。 |
| `start` / `end` | 自动识别 | `{kind:"pad"/"via"/"track", primitiveId:"..."}` 明确绑定图元；`{kind:"free"}` 保留该端点。不同目标位置不明确时拒绝猜测。 |
| `maxEndpointExtension` | 100 mil | 从原端点到目标锚点的最大移动距离；与中段的 `maxDeviation` 分开约束。 |
| `protectedIndices` | 空 | 仅单条路径接口：必须保留的中间点下标；首尾以及落在已有同网铜外框内的点自动保护。 |
| `clearance` | 单条 6、自动 15 | 统一保守障碍检查间距，仍需原生 DRC 核对工程中各类具体间距规则。 |
| `dryRun` | false | true 只读当前环境并返回规划结果，不创建图元、重建铺铜或运行 DRC。 |

例如先调用 `pcb_route_track`：

```json
{
  "net": "SWDIO",
  "layer": 1,
  "width": 6,
  "points": [{"x": 482.3, "y": 669.3}, {"x": 481.5, "y": 803.1}],
  "angleMode": "octilinear",
  "cornerStyle": "chamfer",
  "dryRun": true
}
```

返回 `endpoints` 记录原端点、绑定图元、最终锚点和移动距离。`maxDeviation` 相对端点绑定后的输入路径计算，端点移动单独受 `maxEndpointExtension` 限制。返回 `points` 是整理后的坐标，`changed` 表示路径是否变化，`issues` 区分错误和提示，`ready` 表示能否通过本次预检。该示例需在对应网络的实际板子上预览；文档中的坐标不是通用位置。

## 路径与连接的处理

- 不把焊盘/过孔位置吸附到网格。先解析端点目标并保留原生精确中心，再通过水平、垂直和 45° 过渡解决不共轴端点；不保留自动搜索产生的焊盘边缘终点。
- 自动识别使用旋转后的 RECT（无非零形状修饰）、ELLIPSE、OVAL、过孔圆形和导线胶囊形的实际几何，不使用包围盒角落吸附。不支持的目标形状会报告，不能猜测。已经精确位于过孔中心的连接不会被拉到同位置热焊盘的其他中心。
- 自动模式只识别已经发生铜面接触的端点，空白处自由端点不吸向附近焊盘。绑定指定 ID 时检查网络、层号和移动距离。用于特殊功率焊盘入口或有意分支时可以显式选择 free/preserve；这不免除角度和间距预检。
- 移除重复点，合并共线段，并在偏移预算和障碍约束内简化冗余折线。自动候选路径的选择计入转弯代价。
- 锚点优先于倒角。连接锚点处的直角会保留并提示，避免把一个分支接点切掉。
- 每次替换线段及倒角后复查障碍；最终还检查整段路径的偏移范围。失败不强连，也不以任意角度作为隐式降级方案。
- 单条路径预检全部完成后才开始创建线段。原生 API 若中途失败，错误包含已创建的图元 ID，不宣称操作具有原子性。

## 环境检查与写入后检查

固定焊盘、走线、过孔、弧线、填充和区域使用原生包围盒作保守障碍。复杂形状可能产生误报。自动铺铜的边界不作为整块实心障碍，写入后重建铺铜。板框使用包围盒约束，凹形板框及精确间距需要原生 DRC。

写入后读取仍保留创建 ID 的线段，检查其实际角度及短线段，并用 `endpointsVerified` 报告是否在这些实际线段上确认全部最终锚点。若 EDA 合并/拆分导致 ID 缺失，`geometryVerified` 为 false，并返回 `missingPrimitiveIds`，需要整板检查；铺铜重建或读回失败也会明确报告。

新增 `pcb_check_route_geometry` 是只读工具，支持按网络/铜层筛选，报告：

- 非标准角度、零长度和短线段；
- 同层端点处的普通二度节点转角；
- 焊盘/过孔锚点转角提示，以及排除的多分支节点数。

新增 `pcb_check_route_endpoints` 也是只读工具，可按网络/铜层筛选，`toleranceMil` 默认 0.1、允许 0–1 mil。它检查普通焊盘/过孔的中心是否落在直接连接导线的中心线上，以及线到线是否只有铜面搭接而中心线不相交。偏心属于复核提示，不自动当成断路；宽铜、热焊盘和刻意采用的入口仍需人工判断。不支持的形状列在 `unsupportedTargets`，自由端点和可能的铺铜连接列在 `unclassifiedEndpoints`，不假装已验证这些连接。

角度检查不检查连通性或替代 DRC，也不是完整的铜皮拓扑求交。内置自动布线结束时同时返回此几何检查与 DRC；`routedNets` 同时要求该网络的连接、几何和端点检查通过。

`pcb_execute_code` 仍是原始 JavaScript 执行通道。直接调用 `eda.pcb_PrimitiveLine.create` 会绕过路径整理，不会被偷偷改写；常规布线应使用 `pcb_route_track`。原始代码布线后应单独运行几何、端点检查与 DRC。离线规划可以通过 `scripts/prepare-route-path.mjs` 调用共享的端点绑定及角度策略（JSON 标准输入/输出，单位 mil），但调用方仍须提供障碍或在写入前独立检查精确铜几何。IMU 任务中的 `endpoint_finish.py` 已接入这一工具：对新生成候选使用 30 mil 的整理范围，然后通过原有 Shapely 全计划间距检查；失败回滚该候选，不写入 PCB。历史 seed/缓存走线是已有输入，不会因为重新读取而被批量改写；旧布局缓存必须与当前焊盘位置一致并通过完整检查。

## 生成与验证

共享几何、端点函数及 EDA 处理器是维护入口；不要手工编辑 `src/codegen/generated.ts`。

```bash
npm run port
npm run build
npm run test:regressions
```

回归用例覆盖：原 SWDIO 边缘坐标、旋转/椭圆/椭圆长圆焊盘、过孔及已有导线接入、原生非网格坐标、歧义与错网错层 ID、自由端点、端点移动上限、修正后的障碍、生成代码 dry-run 零写入、写入坐标和异常读回、端点审计以及离线入口的过孔锚点保护。

Windows 端需更新源码并重新构建、重启 MCP 服务进程，使新参数、新工具与生成代码一起生效。此次真实编辑器验证使用了生成后的处理器做只读预览：SWDIO 两端接入正确的原生焊盘中心，角度检查没有告警，预览前后 PCB 图元快照一致。实际写入与读回逻辑通过本地 EDA 模拟测试验证；整板旧线不会被这次代码更新自动改写。
